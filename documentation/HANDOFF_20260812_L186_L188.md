## L-186 finished, and it was never a data question

The six `duplicate_identity` findings carried forward through three
handoffs as "each needs a look at the source: either one annotation is
redundant, or a checker name is wrong." All six were the parser
misreading correct annotations.

The retired format put a free-text SOURCE before the check date:

    # Cross-checked: Hauck et al. 2013 via GPT 2026-08-03 (worksheet.md)

The parser takes the first four-digit year as the check date and
everything before it as the checker identity. A source carrying its own
publication year ate the date, so the model name landed after it and
never entered the identity. Two annotations by two DIFFERENT models read
as one checker written twice.

**Measured, not inferred:** 19 units affected against 20 scored
correctly, and 54 of 134 annotation lines codebase-wide parsed with the
checker outside the identity. Half the completed cross-check work was
scored V3 and described in the audit as "cross-check incomplete
(1/2 models)."

**Tony's ruling: fix the root causes, not the six symptoms.** Three were
found, and the format change addresses all three -- the format was
ambiguous by construction, the scanner's "checker identity" field was
filled with source-plus-model (so two different sources checked by the
SAME model would have earned V2, the "two Claude passes are one leg"
hole), and nothing bound the skill's examples to the parser.

New grammar, checker first:

    # Cross-checked: GPT 2026-08-03 -- Hauck et al. 2013 (worksheet.md)

The `-- <source>` clause is optional. The retired order is now REFUSED as
`legacy_source_first` rather than reconstructed. All 134 lines migrated;
zero `duplicate_identity` remain.

**The store-binding check lives in `skills_index.py`, not the test
suite.** Tony's fact, and it changed the design: "I don't independently
run tests like that unless you ask during the build." A check in a file
nobody runs is not a check. `skills_index.py` runs at the moment a skill
changes, which is the moment the drift is introduced. It asserts every
annotation example in every SKILL.md parses as the scanner reads it.
Tested both ways: clean on the real tree, and it correctly refused when
the retired format was reintroduced by hand.

## The constants pins, and what replaced them

The six constants-provenance failures were NOT drift. Each value was
deliberately corrected on 2026-08-02 by the cross-check batch, with a
`# Corrected:` record, a named source, and two independent checkers. The
test file pinned the pre-correction values and was never updated.

**Tony's rulings, in the order they arrived, each one narrowing it:**

1. Not selective edits. "What I am cautious about is selective edits that
   are effectively superficial."
2. Not a second dictionary. "What I don't think we should do is create a
   second dictionary. Can we create a diff that would alert us to drift
   or intentional revision?"
3. A gap should announce. "Such a gap should announce and we would track
   it down."

**55 pins retired, 18 structural tests kept** -- derivations, orderings,
cross-consistency, completeness. None holds a copy of a measured value,
so none goes stale when a value is corrected. (The count was quoted as
52/21 earlier in the session from a crude heuristic; the accurate AST
pass is 55/18 and six derivation and sanity-band tests were reclassified
as keepers.)

**`constants_change_report.py` replaces them and stores no numbers.** It
asks git what changed in `constants_new.py` since the last commit and
reads both values out of the diff. A deliberate correction moves the
number AND its comment block; corruption moves the number alone. It
covers constants that do not exist yet -- a value added next month is
reported the first time it moves, with nobody writing a test. That
generalisation is Tony's.

**The unaudited-citation finding, which is the part worth remembering.**
The scanner extracts claims only from narrative-role files, and
`test_constants_provenance.py` is `Role: devtool`, so nothing has ever
audited its citations. `test_chromosphere_radii` attributed "~1.5 R_sun"
to Carroll & Ostlie Ch. 11 -- the same chapter the August check read as
~2000 km, about 1.003 R_sun. A false citation, in a file nothing audits,
for four months. Wrong-but-cited is the failure this project treats as
worse than uncited.

## Protocol v3.39

**A Check That Cannot Fail Is Not Passing [CRITICAL]**, added to Part 3
after Verify Execution, Not Appearance. That gate asks whether the code
you edited is the code that runs; this one asks whether the CHECK you are
trusting can produce a failure at all.

Three instances in this one session, each in a different layer, each
indistinguishable from a pass: a skill teaching a format its own parser
could not read; a 55-pin test file no routine executed for ten days; and
`git diff <rev> -- <path>` exiting 0 with empty output for an untracked
path, so "no changes" printed identically whether the file was clean,
untracked, or gone.

That third one is Tony's, found by asking **"what tells us that the git
is working?"** -- a question about a tool that had just reported success.
The gate's confirming test is that question. If the only answer is that
it did not complain, that is not an answer.

The reporter now prints the commit it compared against, by short SHA and
subject, and aborts before that line if git does not track the file.
