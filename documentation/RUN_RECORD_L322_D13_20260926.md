## 1. Why

`exact_rows_report.py` (patch D12) follows each gallery pointer to an
exact row of `constants_new.py` to the line that prints it, through its
PRINTS table, and reports a pointer with no entry as NOT FOLLOWED. It had
no way to say a pointer is read only to place a drawing. Gallery patch 3
adds four such pointers: the magnetotail's drawn radius and drawn end,
which shape the tail while its hover prints the measured rows, and
Earth's two fallback pole rows, which place the axis when no pole of date
is served. Without this patch the report would call all four NOT
FOLLOWED on every run: a permanent warning that is always wrong.

The orrery half already had the category ("Not printed"). This gives the
gallery half the same one. Proposed at session start and confirmed by
Tony, 2026-09-26.

## 2. What the patch changes

- **`exact_rows_report.py`**: a second hand-kept table, DRAWN, keyed like
  PRINTS: the page script, the function, and a piece of the line that
  READS the value. An entry is BROKEN if no line in that function reads
  it, if that line is a print line (then the value is printed and belongs
  in PRINTS), or if no pointer reaches the entry. A drawn-only row is
  listed under "Not printed" with the line that reads it. The summary line
  gains "N drawn only". The four entries:
  `earth_magnetosphere/magnetotail/drawn_radius` and `.../drawn_end` in
  `renderMagnetosphere`, `orientation/pole/ra` and `.../dec` in `basisFor`.
- **Two run records**, this one and gallery patch 3's, into
  `documentation/`.

## 3. How it was verified, in the sandbox

- Against the patched gallery: "7 of 20 exact rows printed at 18 lines
