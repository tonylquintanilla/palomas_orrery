## What the patch changes

- `tools/gallery_cache_builder.py`. On every build it fetches Earth's
  north pole for the day (observer quantity 32, target 399, from the Sun)
  and the Earth-Moon barycenter's orbit (target 3 about the Sun, ecliptic
  of J2000), at the same 0h UT epoch the osculating elements use. It
  serves them, with the tilt worked out between them, as
  `objects.earth.pole_of_date` in `coverage_index.json`, each with its
  source block. It serves `frame_constants` at the top of the same file:
  `KM_PER_AU` and `EARTH_OBLIQUITY_J2000_DEG`, read from
  `data/constants_export.json`, with the orrery commit the export came
  from. Structural check `#P` recomputes the tilt from the served inputs
  and aborts the swap if they disagree. A failed pole fetch leaves
  `pole_of_date` null, prints a `[POLE]` line and a warning, and the build
  goes on.
- `tools/pole_of_date.py`, new. The tilt geometry, copied from the
  orrery's `earth_pole_of_date.py` at `fb8d927e`, with the frame angle as
  a required argument instead of an import. It also holds `#P`'s checker.
- `tools/test_pole_of_date.py`, new, 11 checks. Also run by
  `gallery_maintenance_run.py` as "Pole of date".
- `tools/test_gallery_cache_builder_offline.py`, 201 checks to 210.
- `data/objects_config.json`: one `pole_of_date` block on Earth that asks
  for the fetch. It is outside `features`, so "Cache in step" is
  unaffected, and it holds no numbers.

The page reads none of this yet. It draws as before until patch 2.

**Where the two frame rows sit** (manifest section 5 asks the builder to
report it): `coverage_index.json`, top level, `frame_constants.rows`,
keyed by the row's name in `constants_new.py`.

## Each new check shown failing

- No `pole_of_date` block in the config: 6 offline checks fail.
- The builder's tilt computed with a frame angle off by 1e-6 degree: the
  build itself aborts with `#P earth`.
- The same, with the altered angle also written into the served block
  so `#P` agrees: the offline check against the export's angle fails.
- The frame angle row deleted from the export: 3 offline checks fail,
  and the builder serves the pole with no tilt and says why.
- Inside `test_pole_of_date.py`, three altered-input checks must fail
  every run.

**Two first attempts at those altered inputs could not fail**, and were
replaced. Moving the pole's declination by 2 arcseconds changed the tilt
by only 0.025 arcseconds, because near the celestial pole that moves the
pole sideways to the plane the tilt is measured in. And moving the frame
angle cannot change the ERFA geometry check at all, because ERFA's pole
and ecliptic both pass through the same rotation. The test now alters the
orbit's inclination, which moves the tilt by nearly the full amount
(1.934 arcseconds for 2, 0.998 for 1).
